# MonitorSaver v3.1

`Ctrl` + `Shift` + `Alt` + `L` → **세션 잠금 + 모니터 끄기**. 복귀는 아무 입력이나(마우스/키보드 무관).

밤새 작업(예: Claude Code)을 돌려 두면서 OLED 모니터를 아끼기 위한 용도. 화면만 끄고 세션을 잠근다 — 컴퓨터를 재우거나 끄지 않는다. 전원 관리 설정(절전/최대절전/디스플레이 끄기 시간 등)은 **하나도 건드리지 않으므로**, 밤새 돌리려면 Windows 절전이 꺼져 있어야 한다([전원 설정과의 관계](#전원-설정과의-관계)).

---

## 설치

1. [tools.jdg.dev](https://tools.jdg.dev) 또는 이 저장소의 Releases에서 `MonitorSaver-<버전>.zip`을 받는다.
2. **압축을 풀기 전에** zip 파일 우클릭 → 속성 → 아래쪽 **"차단 해제"** 체크 → 확인.
   (인터넷에서 받은 파일이라 이걸 안 하면 처음 실행할 때 "Windows의 PC 보호" 경고가 뜬다. 떠도 "추가 정보 → 실행"으로 넘어갈 수 있다.)
   PowerShell로 하려면: `Unblock-File .\MonitorSaver-3.1.zip`
3. 원하는 곳에 압축을 푼다. 예: `%USERPROFILE%\MonitorSaver`
4. `Start.cmd` 실행 → 트레이에 모니터 모양 아이콘이 뜬다.
5. 로그온 때마다 자동으로 띄우려면 `Install-Autostart.cmd` (관리자 권한 불필요).

새 PC에서 처음 쓸 때 불안하면 트레이 우클릭 → **"잠금 사용"** 체크를 끄고 먼저 확인한다. 잠기지 않으므로 화면이 안 돌아와도 갇히지 않는다. 아무 키나 눌러 잘 돌아오는 걸 확인한 뒤 다시 켠다.

> 폴더를 옮겼다면 자동 실행을 **다시 등록**해야 한다. 작업 스케줄러에는 등록할 때의 exe 경로가 저장된다.

## 동작

```
핫키 → 핫키 키가 모두 떨어질 때까지 대기(+200ms)
     → LockWorkStation() → 잠금 통지 확인 → 400ms 안정화 → MONITOR_OFF 1회 → 끝
```

그리고 **그 다음부터는 아무것도 하지 않는다.** 깨우기는 Windows 기본 동작에 맡긴다 — 아무 키나 누르거나 마우스를 움직이면 화면이 돌아오고, 잠금화면에서 비밀번호를 입력하면 된다.

손 뗄 때까지 기다리는 이유: 핫키에서 **손을 떼는 동작 자체가 화면을 다시 켜기 때문**이다. 누르자마자 끄면 키를 놓는 순간 도로 켜지고, v3는 재소등을 하지 않으므로 그대로 켜진 채 남는다.

처음에는 "모든 입력이 1.5초 잠잠해질 때까지" 기다리게 했는데, 마우스를 조금만 만지고 있어도 조건이 성립하지 않아 상한 10초까지 늘어졌다. 지금은 `GetAsyncKeyState`로 **핫키 키만** 보므로 마우스는 무관하다. 체감 지연은 잠금 포함 약 1.2초, 잠금 없이는 약 0.6초.

```
0.0s       핫키
0.6~0.8s   손 뗀 것 확인(+여유) → 잠금 요청
0.7~0.9s   잠금 완료 통지 수신 (여기서 이미 보안 확보)
1.1~1.3s   소등 요청 → 모니터 꺼짐
```
(실사용 로그 기준. 손을 떼는 속도에 따라 달라진다.)

### 잠금이 확인되지 않으면 화면을 끄지 않는다 (v3.1)

v3까지는 잠금 요청이 실패하거나 잠금 통지가 오지 않아도 상한(2.5초)이 지나면 "그래도 진행"해서 화면을 껐다. 그러면 **화면은 까만데 세션은 열려 있는** 상태가 되고, 잠긴 줄 알고 자리를 비우게 된다.

v3.1은 잠금 사용(`LockFirst=1`)일 때 잠금이 **확인된 경우에만** 화면을 끈다.

| 상황 | v3.1 동작 |
|---|---|
| 잠금 통지 수신 | 정상 진행 — 안정화 후 소등 |
| 잠금 요청(`LockWorkStation`) 실패 | 화면을 끄지 않음 + 트레이 경고 풍선 |
| 상한(`LockWaitMs`) 안에 통지 없음 | 화면을 끄지 않음 + 경고. 늦게라도 잠겼다면 잠금화면이 켜진 채 남고, Windows가 유휴 시간 뒤에 끈다 |
| 잠금 통지 등록 자체가 안 됨 | 잠그기 전에 멈춤 + 경고. 다음 핫키 때 등록을 다시 시도한다 |
| 잠금 확인 후 소등 직전에 잠금이 풀림 | 화면을 끄지 않음. 소등 직전에 잠금 상태를 다시 확인하고, 잠금 해제 통지가 오면 진행 중인 소등을 취소한다 |
| 이미 잠긴 상태에서 `-blank` (스크립트) | 실행 중인 MonitorSaver가 그 잠금 통지를 받았다면 잠금 요청을 생략하고 안정화 후 소등 |

## v1이 왜 사고를 냈는가 (2026-08-03, 강제 종료)

v1은 "마우스는 무시, 키보드로만 복귀"를 구현하려고 훨씬 복잡한 짓을 했고, 그 결과 **검은 잠금화면에 갇혀 PC를 강제 종료**해야 했다. 실측 로그가 남긴 원인 세 가지:

1. **되끄기 싸움** — 화면이 깨어날 때마다 즉시 되껐다. 3초 동안 DPMS를 8번 토글했다.
2. **잠금 27ms 전에 소등 명령** — `03:07:51.761` 소등 → `03:07:51.788` 잠금. 데스크톱이 전환되는 순간에 DPMS 전환을 걸었다.
3. **잠긴 뒤에 화면을 켜려 함** — 세션이 잠기면 입력 데스크톱이 Winlogon으로 바뀌고, 그때부터 이 프로세스는 화면을 켤 수단이 없다. 4번 시도 전부 실패했다.

그 PC의 주 모니터는 **DisplayPort에 물린 QD-OLED**라 DPMS 토글에 특히 취약했다. DP는 화면을 끌 때 링크 자체를 끊어서, 재협상이 실패하면 검은 화면이 된다.

**v3는 위 셋을 전부 하지 않는다.** 저수준 훅 없음, 감시 루프 없음, 재소등 없음, 강제 켜기 없음. 소등 요청은 한 시점에 한 번(자기 창 → 보조 브로드캐스트)이고 반복하지 않는다.

유휴 시간이 지나면 Windows가 스스로 화면을 끄고 정상 복귀한다. v3는 그 검증된 경로를 그대로 쓴다 — 단지 즉시, 그리고 잠근 채로.

### 포기한 것: "마우스는 무시"

잠금화면은 **보안 데스크톱(Winlogon)** 이라 일반 권한 프로세스는 그 위에서 키/마우스를 구분할 수 없다. 훅도 `GetAsyncKeyState`도 차단된다. 구분을 되살리려면 마우스 장치를 PnP로 비활성화해야 하는데 **관리자 권한이 필요하다.** 이 도구는 관리자 권한 없이 도는 것을 원칙으로 한다.

v1은 이걸 우회하려고 "잠금을 키 입력 시점까지 미루는" 설계를 썼고, 바로 그 복잡도가 사고를 냈다. v3는 마우스 무시를 포기하는 대가로 사고 위험을 제거했다.

| 항목 | 설명 |

| 로그온 시 자동 실행 | **작업 스케줄러** 등록/해제. 관리자 권한 불필요 |

| 로그 열기 | `MonitorSaver.log` |

창은 없다. 로그온 시에도 모달 창을 띄우지 않는다 — 핫키 등록 실패, 중복 실행, 잠금 미확인은 트레이 풍선으로만 알린다(`ShowTrayIcon=0`이면 풍선 없이 로그에만 남는다).

## 자동 실행 — 왜 작업 스케줄러인가

처음에는 `HKCU\...\Run` 레지스트리를 썼는데, **2026-08-11 재부팅 후 실제로 실행되지 않았다.** Defender·SmartScreen·AppLocker 차단 기록도, 오류도 없었다. 그냥 실행되지 않았다.

`Run` 키와 시작 폴더는 **둘 다 탐색기(Explorer)가 로그온 때 처리**한다. 하나가 실패하면 다른 하나도 같이 실패할 수 있다. 그래서 **작업 스케줄러**로 옮겼다 — 별도 서비스가 처리하고, 실패 시 1분 간격 3회 재시도까지 붙는다.

```
작업 이름   MonitorSaver
트리거      로그온 시 (+15초 지연)
권한        Limited (관리자 아님)
재시도      실패 시 1분 간격 3회
```

등록/해제: `Install-Autostart.cmd` / `Uninstall-Autostart.cmd`. 트레이 메뉴의 "로그온 시 자동 실행"도 같은 작업을 만들고 지운다. (`MonitorSaver.exe -autostart on|off`)

## 안 될 때 — 왜 꺼졌는지 확인하기

`Status.cmd` — 실행 여부 + 마지막 생존 시각 + **종료 사유**를 한 화면에 보여준다.

단축키가 안 먹는 경우는 거의 전부 **프로세스가 죽어 있는 것**이다. 트레이 아이콘이 없으면 죽은 것이니 `Start.cmd`로 다시 띄우면 된다.

### 죽은 이유를 어떻게 알아내는가

2026-08-07에 프로세스가 **아무 흔적도 없이** 사라진 적이 있다. 원인을 밝힐 수 없었던 이유는 명확하다 — **작업 관리자 같은 외부 강제 종료(TerminateProcess)는 프로세스 내부 핸들러가 아예 실행되지 않는다.** 앱 안에서 아무리 로깅해도 그 경우는 잡히지 않는다. 그래서 세 겹으로 만들었다:

| 층 | 무엇 | 잡아내는 것 |
|---|---|---|
| 1 | `heartbeat.txt` (30초마다 갱신) | 파일 수정 시각 = **마지막으로 살아 있던 시각** |
| 2 | 예외·종료 로깅 (앱 내부) | 크래시, 세션 종료, 정상 종료 |
| 3 | **감시 프로세스** (별도 프로세스) | **종료 코드** — 강제 종료인지 크래시인지 판별 |

3층이 핵심이다. 종료 코드 해석:

| 코드 | 뜻 |
|---|---|
| `0x00000000` | 정상 종료 (트레이 "종료" 또는 `-quit`) |
| `0x00000001` | **외부 강제 종료** — 작업 관리자 "작업 끝내기" / `taskkill /F` |
| `0xFFFFFFFF` | **외부 강제 종료** — PowerShell `Stop-Process -Force` 등 |
| `0x40010004` | 로그오프/시스템 종료 때 Windows가 정리함 (정상) |
| `0xE0434352` | .NET 처리되지 않은 예외 (로그의 `!!` 항목 확인) |
| `0xC0000005` | 액세스 위반 크래시 |

> **작업 관리자에 `MonitorSaver.exe`가 2개 보이는 것이 정상이다.** 본체 + 감시용. 감시 프로세스는 종료 원인을 기록하고(`AutoRestart=1`이면 다시 띄운다), 화면이나 세션은 절대 건드리지 않는다.

`AutoRestart=1`로 두면 비정상 종료 시 감시 프로세스가 다시 띄운다. 정상 종료, 로그오프/시스템 종료(`0x40010004`), 1분 미만 생존 시에는 재실행하지 않는다. 기본값은 꺼짐.

## 설정 (`MonitorSaver.ini`)

처음 실행할 때 exe 옆에 자동으로 만들어진다. 고친 뒤 트레이 우클릭 → "설정 다시 읽기".

| 키 | 기본값 | 설명 |
|---|---|---|
| `Hotkey` | `Ctrl+Shift+Alt+L` | 예: `Ctrl+Alt+F12`, `Ctrl+Alt+1`(숫자 한 글자는 숫자 키). 수식키(Ctrl/Shift/Alt/Win)가 하나 이상 필요 |
| `LockFirst` | `1` | `0` = 잠그지 않고 소등만 (동작 확인용). 트레이 메뉴로도 토글 |
| `KeyReleaseGraceMs` | `200` | 핫키에서 손을 뗀 뒤 두는 여유 |
| `MaxKeyWaitMs` | `3000` | 키가 안 떨어져도 이 시간이 지나면 진행 |
| `LockWaitMs` | `2500` | 잠금 통지를 기다리는 최대 시간. 그때까지 확인되지 않으면 화면을 끄지 않는다 |
| `LockSettleMs` | `400` | 잠금 확인 후 소등까지 대기 (데스크톱 전환 중에 화면 전원을 건드리지 않기 위함) |
| `KeepSystemAwake` | `0` | 실행 중에만 시스템 절전 억제 (전원 설정 자체는 안 바꿈) |
| `AutoRestart` | `0` | `1` = 비정상 종료 시 감시 프로세스가 다시 띄움 |
| `ShowTrayIcon` | `1` | `0` = 트레이 아이콘도 숨김(완전 무음). 경고 풍선도 안 뜨고, 설정은 ini를 직접 고친 뒤 재시작, 종료는 `MonitorSaver.exe -quit` |

## 문제 해결

**화면이 안 돌아온다** — PC를 강제 종료하기 전에 **모니터 전원 버튼을 껐다 켜세요.** DP 링크가 재협상되면서 대부분 살아납니다. 훨씬 안전합니다.

**핫키가 안 먹는다** — 트레이 아이콘이 있는데도 안 먹으면 다른 프로그램이 같은 조합을 선점했을 수 있다. 시작 시 트레이 풍선으로 알린다. `Hotkey` 값을 바꾸고 "설정 다시 읽기".

**"잠금이 확인되지 않아 화면을 끄지 않았습니다" 풍선이 뜬다** — 회사 정책 등으로 잠금(Win+L)이 막혀 있을 수 있다. Win+L이 되는지 먼저 확인하고, 로그(`MonitorSaver.log`)의 `소등 취소` 줄을 본다.

**화면이 안 꺼진다** — 다른 앱이 화면을 붙잡고 있을 수 있다(`ES_DISPLAY_REQUIRED`):

```
powercfg /requests
```

**전부 멈추기**

```
MonitorSaver.exe -quit
```

응답이 없으면 `taskkill /IM MonitorSaver.exe /F` (본체와 감시용 둘 다 끝난다).

## 전원 설정과의 관계

MonitorSaver는 전원 설정을 바꾸지 않는다. 밤새 작업이 절전으로 끊기지 않게 하려면 Windows 설정에서 **전원 연결 시 절전 = 사용 안 함**으로 두거나, `KeepSystemAwake=1`(실행 중에만 절전 억제)을 쓴다.

배포용 zip은 GitHub Actions가 이 소스에서 직접 빌드해 Releases에 올린다(`.github/workflows/windows-release.yml`).
